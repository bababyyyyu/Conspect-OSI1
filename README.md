Конспект: Сетевая модель OSIМодель OSI (Open Systems Interconnection) — это эталонная семиуровневая модель взаимодействия открытых систем, созданная организацией ISO в 1984 году. Она описывает правила и этапы передачи данных между устройствами в компьютерной сети, превращая сложный процесс в понятную абстрактную схему.Ключевые принципы моделиИнкапсуляция и делкапсуляция: При отправке данные спускаются с верхнего уровня на нижний, обрастая служебной информацией (заголовками) — это инкапсуляция. При приеме идет обратный процесс — декапсуляция.Абстракция: Каждый уровень «общается» только со своими соседями (выше и ниже) и не знает о внутреннем устройстве других слоев. Приложению все равно, идет интернет по Wi-Fi или по кабелю.7 уровней модели OSI (от верхнего к нижнему)7. Прикладной уровень (Application Layer)Суть: Взаимодействие сетевых приложений с пользователем.Функции: Предоставляет программам (браузерам, почтовым клиентам) доступ к сетевым службам.Единица данных: Данные (Data).Протоколы: HTTP, HTTPS, FTP, SMTP, DNS, SSH.6. Уровень представления (Presentation Layer)Суть: Перевод данных в универсальный формат.Функции: Кодирование/декодирование, сжатие данных и шифрование.Единица данных: Данные (Data).Протоколы/Форматы: SSL, TLS, JPEG, ASCII, MPEG.5. Сеансовый уровень (Session Layer)Суть: Управление сессией связи.Функции: Создает, поддерживает и завершает сеанс связи между устройствами. Фиксирует контрольные точки (если связь оборвется, скачивание возобновится с последней точки).Единица данных: Данные (Data).Протоколы: RPC, NetBIOS, L2TP, PPTP.4. Транспортный уровень (Transport Layer)Суть: Доставка данных из точки А в точку Б.Функции: Разбивает большие куски данных на части (сегментация) при отправке и собирает обратно при получении. Отвечает за надежность и исправление ошибок.Единица данных: Сегмент (для TCP) / Датаграмма (для UDP).Протоколы: TCP (гарантирует доставку с контролем получения) и UDP (быстрая передача без контроля — для стриминга, созвонов).3. Сетевой уровень (Network Layer)Суть: Маршрутизация и логическая адресация.Функции: Определяет наилучший физический путь для доставки данных между разными сетями (маршрут). Работает с логическими адресами.Единица данных: Пакет (Packet).Протоколы: IP (IPv4, IPv6), ICMP (утилита ping), OSPF.Оборудование: Маршрутизатор (роутер).2. Канальный уровень (Data Link Layer)Суть: Передача данных внутри одной физической сети.Функции: Проверяет ошибки физического уровня, упаковывает данные в кадры, взаимодействует с сетевой картой и распознает физические адреса устройств.Единица данных: Кадр / Фрейм (Frame).Протоколы: Ethernet, Wi-Fi (IEEE 802.11), PPP.Оборудование: Коммутатор (свитч), сетевая карта. Контролирует физические MAC-адреса.1. Физический уровень (Physical Layer)Суть: Физическая передача сигналов.Функции: Переводит единицы и нули в электрические импульсы, радиоволны или световые сигналы и передает их в физическую среду.Единица данных: Бит (Bit).Оборудование: Кабели (витая пара, оптоволокно), повторители (репитеры), концентраторы (хабы).Шпаргалка для запоминания уровнейЧтобы легко запомнить порядок уровней снизу вверх (от 1 до 7), используется русская мнемоническая фраза:«Федю Колю Съел Тролль, Смыл Посуду После» (Физический, Канальный, Сетевой, Транспортный, Сеансовый, Представления, Прикладной).Английский вариант сверху вниз (от 7 до 1):«All People Seem To Need Data Processing».Сравнение с TCP/IPМодель OSI является теоретической эталонной схемой. На практике в интернете используется стек TCP/IP, который проще и состоит всего из 4 уровней:Прикладной уровень (объединяет 7, 6 и 5 уровни OSI).Транспортный уровень (соответствует 4 уровню OSI).Межсетевой уровень (соответствует 3 уровню OSI).Уровень сетевого доступа (объединяет 2 и 1 уровни OSI).Зачем знать модель OSI на практике?Поиск неисправностей (Траблшутинг): Сисадмины и инженеры ищут поломку по уровням, двигаясь снизу вверх. Если интернет не работает, сначала проверяют, воткнут ли провод (L1), виден ли MAC-адрес (L2), пингуется ли IP (L3) и т.д.Общий язык для инженеров: Фраза «проблема на третьем уровне» сразу говорит специалисту, что нужно проверять настройки маршрутизации или IP-адреса.Если этот конспект нужен вам для конкретной цели, подскажите:Вы готовитесь к экзамену/собеседованию или изучаете для практической работы?Нужно ли добавить текстовый разбор разницы между TCP и UDP?Требуется ли текстовое описание пути сообщения (например, как сообщение в мессенджере проходит по всем уровням)?
